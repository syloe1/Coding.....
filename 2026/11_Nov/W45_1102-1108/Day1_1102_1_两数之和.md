## 📝 题目大意

输入数组 `nums` 和目标值 `target`，返回和为 `target` 的两个元素的**下标**，假设唯一解，不能复用同一元素。

## 🧠 思路

### 方案对比

| 方案 | 思路 | 时间 | 空间 | 采用？ |
|---|---|---|---|---|
| 暴力双层循环 | 枚举 i<j，判断 nums[i]+nums[j]==target | O(n²) | O(1) | |
| 哈希表一次遍历 | 边遍历边查 `target-nums[i]` 是否在表里 | O(n) | O(n) | ✅ |

### 最优思路拆解

1. 维护一个 `map[值]下标`，存已经遍历过的元素。
2. 遍历到 `x = nums[i]` 时，先查 `target-x` 在不在 map 里。
3. 命中就直接返回 `[map[target-x], i]`；没命中再把 `(x, i)` 写进 map。
4. **先查再写**，避免同一个元素被自己匹配到（例如 `target=4, nums=[2,...]` 不能返回 `[0,0]`）。

## 💻 Go 代码

```go
// 去注释纯净版
func twoSum(nums []int, target int) []int {
    seen := make(map[int]int, len(nums))
    for i, x := range nums {
        if j, ok := seen[target-x]; ok {
            return []int{j, i}
        }
        seen[x] = i
    }
    return nil
}
```

## 💻 C++ 代码

```cpp
vector<int> twoSum(vector<int>& nums, int target) {
    unordered_map<int,int> seen;
    for (int i = 0; i < (int)nums.size(); ++i) {
        auto it = seen.find(target - nums[i]);
        if (it != seen.end()) return {it->second, i};
        seen[nums[i]] = i;
    }
    return {};
}
```

## ⏱ 复杂度

| 维度 | 复杂度 | 说明 |
|---|---|---|
| 时间 | O(n) | 一次遍历，哈希查询平均 O(1) |
| 空间 | O(n) | 哈希表最坏存 n-1 个元素 |

## ⚠️ 面试坑点

- **先查后写**：顺序反了会把自己匹配进去。
- 返回下标顺序无所谓，但要保证不是同一个下标。
- Go 的 `map` 在 key 不存在时返回零值，不能用 `m[target-x] != 0` 判断（下标 0 会被误判），必须用 comma-ok。
- C++ 用 `find` 而不是 `[]`，因为 `[]` 访问不存在的 key 会**自动插入零值**，污染哈希表。

## 🔁 变形追问

1. **数组已排序** → 双指针左右夹逼，O(1) 空间。
2. **返回所有数对（去重）** → 排序 + 双指针 + 跳过重复。
3. **三数之和 / 四数之和** → 固定一个 + 内部双指针，O(n²) / O(n³)。

## ✅ 自测三问

1. 为什么用 `map[int]int` 而不是数组？（答：值域离散，无法开数组）
2. 如果存在多组解，题目要求全部返回，怎么改？（答：找到不立即 return，继续遍历到底，注意去重）
3. Go 里 `seen[x] = i` 放在 `if` 前面会出什么 bug？（答：当 `target-x == x` 时，第一轮就命中自己，返回 `[i, i]`）
